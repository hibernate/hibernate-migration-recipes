= Hibernate Migration Recipes

https://docs.openrewrite.org[OpenRewrite] recipes for upgrading applications across versions of https://hibernate.org/[Hibernate] projects.

The intent is to cover migrations across the Hibernate family of projects. The initial recipes support Hibernate ORM; recipes for other Hibernate projects will be added over time. Available migration paths and their limitations are listed below.

See link:CONTRIBUTING.adoc[the contributor guide] for the project layout, custom test SourceSets, and fixture-generation workflow.

== Selecting recipes

Select a recipe by its identifier, not its YAML filename. A composite recipe groups related changes for an upgrade; individual recipes let you select specific conversions. Choose recipes for the Hibernate project and version you are upgrading.

== Available migrations

=== Hibernate ORM 7.4 to 8.0

This unreleased project currently provides these groupings:

* `org.hibernate.migration.recipes.jpa4`: JPA 3.x to 4.0 for Hibernate applications.
* `org.hibernate.migration.recipes.orm80`: ORM 7.4 to 8.0; currently delegates to the JPA grouping.

Individual recipes live in `org.hibernate.migration.recipes.jpa4`:

* `MigrateNamedQueryToStatement`
* `UpdatePersistenceXmlVersion`
* `MigrateEntityManagerGetDelegate`
* `MigrateMapKeyNameToValue`

For example, select `org.hibernate.migration.recipes.jpa4.MigrateMapKeyNameToValue` to run only that conversion. The previous package and grouping names have been replaced; there are no compatibility aliases.

These recipes do not upgrade dependency coordinates. Java matching requires the application's source JPA API on the parser classpath.

==== Deferred and unsupported cases

Neither grouping runs `MigrateTemporalAnnotation`. That recipe remains separately selectable as `org.hibernate.migration.recipes.jpa4.MigrateTemporalAnnotation`, with its existing behavior. Its general type replacement can affect unrelated Date/Calendar usages in the same file, break initializers/accessors, and change timezone semantics. It has not been hardened; redesign is deferred.

Named-query conversion supports literal UPDATE, DELETE, and INSERT operations and preserves query text. Constants, concatenations, CTEs, leading query comments, explicit incompatible annotation members, and conflicting target containers require review. Native statements with result clauses or unsupported quoting/multiple statements remain unchanged. This is a bounded lexical check, not validation of arbitrary HQL or SQL.

MapKey annotations specifying both name and value remain unchanged, even when equal. XML descriptors with unsupported namespaces, versions, or schema declarations remain unchanged. Delegate conversion targets attributed EntityManager calls and emits `unwrap(java.lang.Object.class)`; independently declared overrides, method references, and name-resolution conflicts require review.

==== Validation baseline

The ORM migration is validated from Hibernate ORM 7.4.11.Final with JPA 3.2.0 to ORM 8.0.0.Beta3 with JPA 4.0.0-M7. These are validation versions, not configurable recipe options.

== Reviewing skipped migrations

Skipped recognized candidates appear in the OpenRewrite data table `org.hibernate.migration.recipes.table.SkippedMigrations`, with the leaf recipe, source path, original line/column, subject, stable reason code, and explanation. Source comments or markers are not added.

For example, an application using the ORM migration can enable report export as follows, once the OpenRewrite Gradle plugin and this recipe JAR are configured:

[source,groovy]
----
rewrite {
    activeRecipe("org.hibernate.migration.recipes.orm80")
    exportDatatables = true
}
----

The https://docs.openrewrite.org/reference/gradle-plugin-configuration[Gradle plugin documentation] describes data-table export to `build/reports/rewrite/datatables/<timestamp>`. Review this report alongside the generated changes. A skipped candidate is not a successful migration.
