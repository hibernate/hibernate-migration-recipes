= Hibernate Migration Recipes

https://docs.openrewrite.org[OpenRewrite] recipes for upgrading applications across versions of https://hibernate.org/[Hibernate] projects.

The intent is to cover migrations across the Hibernate family of projects. The initial recipes support Hibernate ORM; recipes for other Hibernate projects will be added over time. Available migration paths and their limitations are listed below.

See link:CONTRIBUTING.adoc[the contributor guide] for the project layout, custom test SourceSets, and fixture-generation workflow.

== Selecting recipes

Select a recipe by its identifier, not its YAML filename. A composite recipe groups related changes for an upgrade; individual recipes let you select specific conversions. Choose recipes for the Hibernate project and version you are upgrading.

For ORM 7.4 to 8.0, select `org.hibernate.migration.recipes.orm80` for the comprehensive migration, including supported deprecated APIs and configuration, or `org.hibernate.migration.recipes.orm80-required` for the required migrations. Required recipes may also perform ancillary edits, such as descriptor version updates. Neither composite selects temporal modernization or Hibernate platform adoption. See the link:migrations/orm80.adoc[ORM migration guide] for membership and limitations.

== Reviewing skipped migrations

Skipped recognized candidates appear in the OpenRewrite data table `org.hibernate.migration.recipes.table.SkippedMigrations`, with the leaf recipe, source path, original line/column, subject, stable reason code, and explanation. Source comments or markers are not added.

For example, an application using the ORM migration can enable report export as follows, once the OpenRewrite Gradle plugin and this recipe JAR are configured:

[source,groovy]
----
rewrite {
    activeRecipe("org.hibernate.migration.recipes.orm80")
    exportDatatables = true
}
----

The https://docs.openrewrite.org/reference/gradle-plugin-configuration[Gradle plugin documentation] describes data-table export to `build/reports/rewrite/datatables/<timestamp>`. Review this report alongside the generated changes. A report row identifies a skipped or partially migrated candidate; review its reason and any explicit versions retained in the output.
