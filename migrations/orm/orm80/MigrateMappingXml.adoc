= MigrateMappingXml
:toc:

link:index.adoc[Hibernate ORM 7.4 to 8.0 migration]

[[_MigrateMappingXml]]
Recipe name is `org.hibernate.migration.recipes.orm80.MigrateMappingXml`.

Migrates Hibernate's `mapping.xml` files:

* updates version to 8.0
* converts Hibernate mapping namespace declarations and matching schema-location pairs to HTTPS
* migrates legacy table and column comment attributes to elements
* removes ignored many-to-many orphan-removal
* migrates versioning exclusions to nested `exclude-from-versioning` elements

See link:xml-descriptors.adoc[shared XML descriptor behavior] for shared eligibility and schema metadata rules.

== Conversions

Canonical HTTP schema URLs are upgraded to HTTPS, including in version 8.0
documents. Both HTTP and HTTPS mapping namespaces are accepted for versions
7.0 and 8.0. Default and prefixed namespace declarations, including nested
redeclarations and unused aliases, are converted to
`https://www.hibernate.org/xsd/orm/mapping`. Prefix names and foreign namespaces
are preserved; ordinary attribute values, text, and comments are not rewritten.

A matching `xsi:schemaLocation` pair is converted to the HTTPS namespace and
`https://www.hibernate.org/xsd/orm/mapping/mapping-8.0.xsd`. HTTP and HTTPS
namespace forms identify the same schema family; declaring a pair for each is
a conflict. Missing pairs are not added, and unrelated pairs and whitespace
are preserved. Namespace conversion is atomic with version, schema, and content
changes.

=== Comment attributes

`org.hibernate.migration.recipes.orm80.MigrateMappingXml` moves unqualified comment attributes to child elements:

[source,xml]
----
<table name="books" comment="Books &amp; editions"/>
----

becomes:

[source,xml]
----
<table name="books"><comment>Books &amp; editions</comment></table>
----

Comment elements are placed in the order required by schema 8.0. Text values are preserved after XML attribute normalization, with XML escaping applied once. Empty values are supported. XML comments and unrelated child elements are retained. If one existing comment
child has the same semantic value, only the redundant attribute is removed.

=== Ignored many-to-many orphan removal

`org.hibernate.migration.recipes.orm80.MigrateMappingXml` removes the unqualified `orphan-removal` attribute from schema-defined `<many-to-many>` elements. Hibernate never processed this attribute, so removing it preserves existing behavior. Both `true` and `false` values are removed, including in documents already marked as version 8.0.

The attribute remains on `<one-to-many>` and `<one-to-one>`, where it is supported. Foreign-namespace attributes, unrelated XML contexts, and JPA entity-mapping documents are unaffected. Removal is part of the same document migration as version and comment changes; a conflict elsewhere leaves the entire document unchanged.

=== Versioning exclusions

Unqualified `optimistic-lock="false"` (or `"0"`) on basic, embedded,
element-collection, to-one, to-many, any, and many-to-any mappings becomes a nested
`<exclude-from-versioning/>`. Explicit `true` and `1` remain unchanged because
inclusion can override annotation defaults. Omitted attributes are not changed.

Legacy `<excluded-from-versioning name="title"/>` entries under `<attributes>`
move into the uniquely named supported mapping as `<exclude-from-versioning/>`.
Existing nested exclusions are reused. The new child precedes `mutable` and
`on-delete` where required by the target schema. Comments are preserved.

Missing, ambiguous, or unsupported named targets, extra legacy-element data, and
invalid boolean values produce `XML_VERSIONING_EXCLUSION_UNRESOLVED`.
Explicit inclusion combined with exclusion, or duplicate nested exclusions,
produces `XML_VERSIONING_EXCLUSION_CONFLICT`. These diagnostics leave the entire
document unchanged. Foreign namespaces and unrelated paths are unaffected.

== Supported inputs

An `entity-mappings` root in either the HTTP or HTTPS Hibernate mapping namespace, with version 7.0
or 8.0. Custom filenames and namespace prefixes are supported.

Comment conversion applies to schema-defined uses of `table`, `secondary-table`, `collection-table`, `join-table`, `table-generator`, `column`, and `join-column` types, including aliases such as `inverse-join-column`. Matching includes the enclosing schema context and namespaces.

== Manual review

JPA mapping comments and arbitrary elements with the same local names are not
converted.

Different values, multiple existing comment children, duplicate comment attributes, and unresolved entity values remain unchanged with `XML_COMMENT_CONFLICT` diagnostics. Any such conflict leaves the entire document unchanged, including its namespace declarations, version, and schema reference. The recipe also handles version 8.0 documents containing legacy comment attributes.
