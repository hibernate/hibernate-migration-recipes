= Modernize @Temporal mappings

== Selecting the recipe

Select `org.hibernate.migration.recipes.temporal.MigrateTemporalAnnotation` explicitly for `@Temporal` modernization. It coordinates supported scalar Date/Calendar fields, direct getters/setters, initializers, assignments, and callers across the sources supplied to one execution. Both field annotations and direct getter annotations are supported. Simple local aliases, null comparisons, and transfers between compatible converted properties are supported; unrelated usages retain their types. Complex accessors, overridden or overloaded accessor contracts, escaping values, legacy temporal operations, collections, and custom mappings leave the affected property and dependent conversions unchanged with a diagnostic. External clients and reflection require review.

[NOTE]
The link:orm80.adoc[ORM 8.0 Migration] does not run this migration.  It must be run separately.


== Enabling with Gradle

With the OpenRewrite Gradle plugin applied and this project's recipe JAR added to the `rewrite` dependency configuration, add this to your application's `build.gradle` to use the default settings:

[source,groovy]
----
rewrite {
    activeRecipe("org.hibernate.migration.recipes.temporal.MigrateTemporalAnnotation")
    exportDatatables = true
}
----

Preview the changes with `./gradlew rewriteDryRun`, then apply them with `./gradlew rewriteRun`.
See the https://docs.openrewrite.org/reference/gradle-plugin-configuration[OpenRewrite Gradle plugin documentation] for plugin and dependency setup.

== Configuration

* `DATE` always maps to `LocalDate`
* `TIME` always maps to `LocalTime`
* `TIMESTAMP` can map to a number of types controlled by `#timestampTarget` -
  ** `INSTANT` (default) selects `Instant`
  ** `LOCAL` selects `LocalDateTime`
  ** `OFFSET` selects `OffsetDateTime`
  ** `ZONED` selects `ZonedDateTime`.

For value conversions (initializers, assignments, etc.) the source of timezone information can come from a number of sources -

* With `honorCalendarTimeZone` omitted or true, a source Calendar's timezone takes precedence
* For `Instant` no timezone information is needed
* `OffsetDateTime` uses `#offset`
* `ZonedDateTime` uses `#zoneId`
* `LocalDate`, `LocalTime` and `LocalDateTime` leverage `#localTimezoneSource` to determine the timezone source -
  ** `OFFSET` specifies to use `#offset`
  ** `ZONE_ID` specifies to use `#zoneId`
  ** `SYSTEM` says to use the application's default zone at runtime

[NOTE]
Missing required settings leave the entire attribute unchanged; malformed supplied offsets/zones invalidate configuration.

For example, save this custom recipe in `rewrite.yml` in your application's project directory:

[source,yaml]
----
type: specs.openrewrite.org/v1beta/recipe
name: com.example.ModernizeTemporal
displayName: Modernize temporal fields
description: Convert supported temporal fields using an explicit local timezone policy.
recipeList:
  - org.hibernate.migration.recipes.temporal.MigrateTemporalAnnotation:
      timestampTarget: INSTANT
      localTimezoneSource: ZONE_ID
      zoneId: Europe/Paris
      honorCalendarTimeZone: true
----

Select that configured recipe in `build.gradle` instead of the default recipe:

[source,groovy]
----
rewrite {
    activeRecipe("com.example.ModernizeTemporal")
    exportDatatables = true
}
----

Converted value expressions preserve null and evaluate the original expression once. Visible custom TimeZone construction or mutation conservatively blocks Calendar conversions that honor its timezone across the supplied source batch; Instant conversions and explicitly configured timezone overrides are unaffected. Changing mutable legacy values to immutable java.time types is an explicit data-model choice. Review callers outside the supplied source set, reflection/generated accessors, custom Calendar/TimeZone implementations, and existing data/schema compatibility. The recipe does not change Hibernate JDBC timezone or storage settings. In particular, a ZonedDateTime Java value does not guarantee that the database retains its regional zone ID.

See link:../README.adoc#_reviewing_skipped_migrations[reviewing skipped migrations] for diagnostic reports.
