= Hibernate ORM 7.4 to 8.0

Select `org.hibernate.migration.recipes.orm80` for the aggregate ORM 7.4 to 8.0 upgrade. It includes JPA 3.x to 4.0 migration for Hibernate applications and Hibernate mapping XML migration, including version updates, comments, and removal of ignored many-to-many orphan removal.

== Enabling with Gradle

With the OpenRewrite Gradle plugin applied and this project's recipe JAR added to the `rewrite` dependency configuration, add this to your application's `build.gradle`:

[source,groovy]
----
rewrite {
    activeRecipe("org.hibernate.migration.recipes.orm80")
    exportDatatables = true
}
----

Preview the changes with `./gradlew rewriteDryRun`, then apply them with `./gradlew rewriteRun`.
See the https://docs.openrewrite.org/reference/gradle-plugin-configuration[OpenRewrite Gradle plugin documentation] for plugin and dependency setup.

== Individual recipes

Individual recipes live in `org.hibernate.migration.recipes.jpa4`:

* `MigrateNamedQueryToStatement`
* `MigratePersistenceXml`
* `MigrateOrmXml`
* `MigrateEntityManagerGetDelegate`
* `MigrateMapKeyNameToValue`

Hibernate-specific recipes live in `org.hibernate.migration.recipes.orm80`:

* `MigrateMappingXml`
* `MigrateQueryFlushMode`

`MigrateQueryFlushMode` replaces Java references to `org.hibernate.query.QueryFlushMode`
with `jakarta.persistence.QueryFlushMode`, including static imports, declarations,
and named-query annotation values. The constants `FLUSH`, `NO_FLUSH`, and `DEFAULT`
and existing query method calls are preserved. It does not convert other flush-mode
enums or class names in strings.

See link:xml-descriptors.adoc[the XML migration guide] for supported namespaces, versions, package descriptors, and comment handling.

For example, select `org.hibernate.migration.recipes.jpa4.MigrateMapKeyNameToValue` to run only that conversion. The former `org.hibernate.migration.recipes.jpa4` aggregate has been removed; select `org.hibernate.migration.recipes.orm80` instead. Individual recipe identifiers are unchanged. The previous package and grouping names have been replaced; there are no compatibility aliases.

These recipes do not upgrade dependency coordinates. Java matching requires the application's source JPA API on the parser classpath.

== Limitations and optional migrations

The aggregate does not run temporal conversion. See link:temporal-annotation.adoc[Modernize @Temporal mappings] for that independently selected migration.

Named-query conversion supports literal UPDATE, DELETE, and INSERT operations and preserves query text. Constants, concatenations, CTEs, leading query comments, explicit incompatible annotation members, and conflicting target containers require review. Native statements with result clauses or unsupported quoting/multiple statements remain unchanged. This is a bounded lexical check, not validation of arbitrary HQL or SQL.

MapKey annotations specifying both name and value remain unchanged, even when equal. XML descriptors with unsupported namespaces, versions, or schema declarations remain unchanged. Delegate conversion targets attributed EntityManager calls and emits `unwrap(java.lang.Object.class)`; independently declared overrides, method references, and name-resolution conflicts require review.

== Validation baseline

The ORM migration is validated from Hibernate ORM 7.4.11.Final with JPA 3.2.0 to ORM 8.0.0.Beta3 with JPA 4.0.0-M7. These are validation versions, not configurable recipe options.

See link:../README.adoc#_reviewing_skipped_migrations[reviewing skipped migrations] for diagnostic reports.
